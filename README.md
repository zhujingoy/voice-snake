# Voice Snake / 语音贪吃蛇

通过“上、下、左、右”操控的网页贪吃蛇游戏，面向 Windows、macOS 电脑。玩家手动启动并授权麦克风后，通过语音完成转向、暂停、继续、重开和结束。

## 作品定位

参赛方向为“灵矽应用：语音类游戏”。网页承担棋盘展示、游戏规则和交互反馈；电脑麦克风的语音输入通过识别适配器转为标准命令，控制同一套游戏逻辑。

设计重点是短口令操作、明确的指令反馈和识别异常时的安全暂停。方向判断采用固定口令映射，不依赖大模型决策。

试玩：[网页游戏](https://zhujingoy.github.io/voice-snake/)。下载：[v0.2.0-rc.1 候选运行包与合成预演](https://github.com/zhujingoy/voice-snake/releases/tag/v0.2.0-rc.1)。四环境真实语音验收结论见[测试报告](docs/validation.md)。

## 本地运行

使用 Node.js 18 或更新版本及 npm。在仓库根目录执行：

```sh
npm ci --ignore-scripts
npm run setup:voice
npm start
```

打开终端打印的地址，默认 `http://localhost:4173`；端口占用时服务自动选择后续端口。默认使用本地中文识别：首次准备下载约 42MB 的中文模型，模型加载完成并授权麦克风后，倒计时三秒进入游戏。已有对应模型时准备脚本跳过下载，浏览器缓存按站点分别保存。其后通过“上、下、左、右、暂停、继续、重新开始、结束游戏”操作。

巡航速度 500ms/格，方向指令可提前触发下一步，连续网格移动最短间隔 100ms。吃食物加 10 分；撞墙或撞到自己结束本局，填满棋盘通关。暂停和结算继续监听，重开不需要再次点击。麦克风断开时暂停，点击“恢复语音通道”重新连接后，仍需说“继续”或“再来一局”。

语音模式包含边缘缓冲：下一步将撞墙时，额外停留最多 1.2 秒等待语音转向，显示倒计时并将棋盘边框变为黄色。收到可避开边界的合法方向后立即恢复移动；无指令或无效方向不会延长缓冲，超时仍撞墙结算。不会自动转弯或穿墙，撞自身不提供缓冲。这是操作容错，不代表识别延迟变短。

本地识别采用限定游戏口令的词表和 `fast-v1` 模型配置：每 256 个采样（16kHz 下 16ms）发送音频，模型按 6 个输入特征帧的小块解码，约 128ms 安静后主动确认短句。本地方向 interim 稳定约 16ms 后提前接收，在线备用保留约 40ms 窗口，final 均直接接收；下一帧或最短步间隔到期即转向，不再等完整巡航周期。其他操作仍需最终结果。稳定窗口内修订可取消或重新计时，提前接收后的修订无法撤销方向。同一结果的后续确认不会重复执行。更短的稳定与静音窗口可能增加误触或截断较慢口令的风险，仍需真人回归。网页的“识别结果到实际转向”不是语音端到端延迟。

仅用于开发：在地址后加 `?debug=1`，打开文本模拟输入，点击开始后可输入口令操控真实棋盘。此模式明确标为“文本模拟”，不请求麦克风，不计入真实语音验收。普通入口不提供键盘转向或局内操作按钮。

启动前可切换“浏览器在线识别”作为备用，不会自动切换或静默上传音频。Windows、macOS 上的 Chrome 和 Edge 真实语音验收均已通过，记录见[测试报告](docs/validation.md)；具体识别模式与版本明细待归档。

## 自动测试

```sh
npm test
```

91 项基础检查覆盖口令、门控、两种识别器生命周期、音频分块及资源释放、模型配置、游戏规则、边缘缓冲、会话协调、本地 HTTP 服务与可选录屏。浏览器集成检查为 `node tests/browser.test.cjs`，需另有 Playwright 与可用浏览器；可通过 `PLAYWRIGHT_MODULE` 指定预装模块，通过 `BROWSER_EXECUTABLE` 指定浏览器路径。该检查启动并清理独立测试服务，以模拟 ASR 验证普通入口，截图写入忽略目录 `test-results/`。

干净目录复现运行 `npm run verify:clean`，需 Git、Node.js、npm 和可访问 npm 注册表与模型下载源的网络。脚本将 Git 可见源码（包括未提交变更）复制到独立的 `test-results/clean-*`，不复制现有依赖、模型或结果，然后依次安装依赖、测试和首次准备模型。`verification.json` 记录基准提交、工作区状态、源码 SHA-256 清单和每步结果，不能把有未提交变更的运行宣称为该基准提交的精确验收。产物留在忽略目录供检查；此步骤不代替新电脑、macOS 或真实麦克风测试。

本地模型音频检查：Windows 上运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/generate-speech.ps1`，通过已安装的 Microsoft Huihui Desktop 生成 13 条合成录音，再运行 `npm run test:local-model`。它使用真实 Vosk 和 AudioWorklet 解码并检查默认游戏入口，但以生成音频替代麦克风，不采集真人声音；原始结果写入 `test-results/local-model.json`。

四环境真实语音验收已通过；正确率、端到端延迟的量化数据尚未提供，见测试报告。

验收 CSV 可通过 `npm run --silent report:acceptance -- <记录.csv> --environment "环境及识别模式" --revision "被测提交及工作区状态"` 生成 Markdown 汇总，统计成功、失败、未测、误触和有证据的成功样本延迟。填写与统计口径见[实机验收记录](docs/acceptance-record.md#汇总)。新增的 9 项统计工具测试纳入 `npm test`，不属于游戏功能或真实语音验收结果。

## 隐私与运行条件

默认本地识别在浏览器 Worker 内处理音频，不需要 API 密钥，运行时不上传音频；中文模型来自 Vosk 发布方，下载与打包脚本见 `tools/prepare-model.cjs`，产物保存在忽略目录 `.models/`。脚本保留模型权重，仅通过 `tools/voice-profile.cjs` 设置 `frames-per-chunk=6`，输出带 `fast-v1` 版本名的归档，避免使用旧模型缓存；已有原始归档时本地重打包，无需重复下载。首次加载后 Vosk 会将模型缓存到浏览器 IndexedDB（不是音频或识别日志）。浏览器在线备用通道可能由厂商处理音频，可用性受网络、地区及浏览器策略影响。默认不持久化音频或识别日志。仅在 `?review=1` 入口主动点击录制后，录像及事件保存在页面内存，用户可下载为本地文件，不自动上传；普通入口没有录屏控件。

本地服务仅绑定回环地址，用于开发验证。外部部署要求 HTTPS；需要服务密钥的识别方案由后端或短期凭证接入，密钥不放入网页。

## 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| 中文模型加载失败 | 先运行 `npm run setup:voice`，确认成功后再启动服务；首次准备需联网，不能只复制 web 目录 |
| 无法授权或没有收音 | 检查浏览器站点麦克风权限、操作系统隐私设置和默认输入设备；使用 localhost，本地模式查看输入电平 |
| 失焦、切页或音频中断后暂停 | 回到前台；若语音通道已断开，先恢复通道，再说“继续”，不会自动恢复移动 |
| 识别了方向但没有转向 | 检查是否直接反向、同向、局面已暂停或已结束；普通方向只能在游戏中执行 |
| 端口占用或打开后不是当前版本 | 使用此次启动终端打印的 URL；服务会选择后续端口，不要固定访问旧服务 |
| 在线通道不可用 | 在线服务受浏览器与网络影响；停止监听后显式选择本地模式再连接，不会静默切换 |
